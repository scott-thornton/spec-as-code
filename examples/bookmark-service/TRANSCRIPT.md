## What the transcript shows

- `spc plan` produced a 7-task DAG (inspect → implement → test → verify) with
  explicit write targets, and flagged two genuine ambiguities as follow-ups
  (tag-API shape; CSV line endings/empty-tags) instead of inventing them.
- With `parallelism: 2` the two disjoint writers (tags in `src/index.mjs`,
  CSV in `src/export.mjs`) executed CONCURRENTLY in per-task worktrees and
  merged deterministically (`PATCH_MERGED` for both, no conflicts).
- One provider flake (thinking-only response) failed the CSV-test task after
  retry; its dependent verify task was correctly BLOCKED - no false success,
  and the run still reached `succeeded` because the properties were verified
  by deterministic evidence (the tags test file covered the CSV cases).
- The public `exportJson()` contract survived untouched (BOOK-C01 green via
  the original, unmodified tests).
- Two open non-blocking follow-ups remain for the human: the tag-input API
  shape (the planner chose `listBookmarks(tag)`), and semicolons inside tag
  values.

A papercut this walkthrough caught and fixed in the tool itself: `spc plan`
leaves `.spc/plans/*.json` untracked, which used to trip apply's dirty-tree
preflight; untracked `.spc/` state no longer gates execution.
